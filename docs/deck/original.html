Think, act, observe, repeat until the task is complete.

User prompt“Check my attendance and email professor the report”
  1. ThinkReason about the user request. LLM analyzes the query and decides what needs to be done.
  2. Select toolChoose the best tool(s) to use. Agent selects tools like PyJIIT, Gmail, Calendar, Browser, etc.
  3. ActExecute the selected tool(s). The agent calls the tool with required arguments and performs the action.
  4. ObserveGet the result from the environment. Tool response is observed and added to the agent state as context.
  5. Reason againDecide next step based on observation, to continue or finalize the task.
  6. Final responseReturn structured final response (JSON / Text) to the user.

Steps 1 to 5 repeat until the task is completed.

Example flow

User prompt, agent reasons, selects tools, executes action, observes result, repeats if needed, returns final response.

Context engine and memory awareness12

Multi-store memory and retrieval dynamics

A hybrid memory system that combines semantic, relational, and transactional data for intelligent, persistent recall.

1. The triple-store persistence layer

Vector store (OpenSearch)
Captures unstructured semantic meaning. Uses k-NN (k-Nearest Neighbors) to find contextually similar past interactions.
Knowledge graph (Neo4j)
Captures structured relationships. Enables multi-hop reasoning by connecting entities (e.g., mapping a found author to previously read papers).
Relational database (PostgreSQL)
The absolute source of truth. Handles temporal data, precise session logs, and strictly schema-bound metadata.

Unstructured (meaning), structured (relationships), transactional (truth).

2. The mathematical engine: hybrid retrieval

Relying purely on vectors misses exact keywords; relying on keywords misses context. We must fuse them.

The formulation (Reciprocal Rank Fusion, RRF)

$$\mathrm{RRF}_{score}(d) = \sum_{i=1}^{N} \frac{1}{k + rank_i(d)}$$
\(d\)The specific document/memory being evaluated.
\(rank_i(d)\)The rank of the document in search system \(i\) (e.g., its rank in the Vector search vs. its rank in the BM25 Keyword search).
\(k\)A smoothing constant (set to 60) to prevent a #1 rank in a single system from dominating the overall score.

Why hybrid? This fusion balances semantic understanding (vector) with lexical precision (keyword) and factual accuracy (relational), providing the most relevant and trustworthy context.

3. Context injection and pruning

  1. The query trigger

    The agent’s current ReAct “Observation” automatically triggers a parallel query across all three databases.

  2. Dynamic pruning

    The RRF scoring mechanism ranks the combined results, strictly pruning low-value memories to prevent LLM context-window overflow and hallucination.

  3. State update

    The highest-scoring memories are instantly injected into the LangGraph state matrix, granting the agent “infinite” cross-session recall without the token cost.

Query, prune, inject.

Why this architecture?

Richer recall. Combines meaning, relationships, and facts.

Higher accuracy. Reduces hallucinations with factual grounding.

Infinite context. Persistent cross-session memory at scale.

Agentic advantage. Enables smarter decisions, planning, and execution.

Context engine and memory awareness13

The mathematical engine: memory decay

Memories naturally fade unless reinforced. We model this decay to surface what’s most relevant now. This engine keeps memory fresh, relevant, and self-managing.

The memory decay formula

\(W(t) = I \cdot e^{-\lambda \cdot \Delta t} \cdot U \cdot C\)
\(I\)base_importance (0–1), prior importance: how intrinsically important is this claim?
\(\lambda\)decay_rate (per tier or segment). Higher λ = faster forgetting (Ebbinghaus curve)
\(\Delta t\)days since last_accessed_at (or created_at if never accessed)
\(U\)usage multiplier, min(1.0 + 0.05 × access_count, 2.0), capped at 2×: retrievals strengthen memory (spacing effect)
\(C\)confidence score (0–1), belief confidence: how certain are we this claim is true?

How λ (lambda) is chosen

We choose a target half-life \(t_{1/2}\) for each tier, then solve \(t_{1/2} = \ln 2 / \lambda \approx 0.693 / \lambda\) (time for weight to decay to ~50%).

Permanentnever00.0

The science behind the formula

1. Ebbinghaus forgetting curve

Ebbinghaus discovered memory retention follows exponential decay: \(R(t) = e^{-t/S}\), where \(R(t)\) is the fraction retained (0 to 1), \(t\) the time elapsed and \(S\) the stability (higher \(S\) = slower forgetting). In our system \(\lambda = 1/S\): higher λ, lower stability, faster decay.

2. Spacing effect (U)

Each retrieval strengthens the memory. More accesses = slower future decay: \(U = \min(1.0 + 0.05 \times access\_count,\ 2.0)\). The cap at 2× prevents runaway inflation.

3. Bayesian confidence weighting (I · C)

Two multipliers encode prior importance and evidential confidence: \(I\) = base_importance (0–1), how important is this claim; \(C\) = confidence (0–1), how certain are we it’s true. Low importance or low confidence = self-pruning.

Example: how decay works

Claim “User prefers dark mode”, tier long-term, segment preferences. \(I = 0.8\), \(C = 0.9\), access_count 12, last accessed 10 days ago. \(\lambda = \max(0.005, 0.0) = 0.005\), \(\Delta t = 10\), \(U = \min(1.0 + 0.05 \times 12, 2.0) = 1.6\).

\(W(t) = 0.8 \cdot e^{-0.005 \cdot 10} \cdot 1.6 \cdot 0.9 = 0.8 \cdot 0.9512 \cdot 1.6 \cdot 0.9 = \mathbf{1.10}\)

Still strong.

When is a memory stale? When \(W(t) < 0.05\), the memory is marked stale and eventually archived.

Key takeaways

Exponential decay (Ebbinghaus) models natural forgetting.

Retrieval strengthens memory (spacing effect).

Importance and confidence encode what and how much we believe.

Low-weight memories self-prune, keeping the system lean and relevant.
